# CEP Customer Management API Documentation

## 1. Overview

This document describes the API requests contained in the Postman
collection `CEP_CustomerManagement_NhanHTT`.

**Base URL**

``` text
{{url}} = https://localhost:7137
```

The collection uses these variables:

  Variable   Value / Purpose
  ---------- ------------------------------------------------------
  `url`      `https://localhost:7137`
  `token`    JWT token saved automatically after successful login

Protected Customer APIs send:

``` text
Authorization: Bearer {{token}}
```

## 2. Authentication

### Đăng Nhập

**Method:** `POST`\
**Endpoint:** `{{url}}/api/Auth/login`\
**Authentication:** No Auth

Request body:

``` json
{
  "username": "admin",
  "password": "Admin@123"
}
```

The Postman test script reads the login response. When the response
status is `200` and `response.data.token` exists, it stores the JWT in
the collection variable `token`. If login fails, the existing token is
removed.

Recommended first step when testing the collection:

``` text
Đăng Nhập
    ↓
JWT saved to {{token}}
    ↓
Call protected Customer APIs
```

## 3. Customer APIs

### 3.1 Lấy Danh Sách Khách Hàng

**Method:** `GET`\
**Endpoint:**

``` text
{{url}}/api/Customers?pageNumber=1&pageSize=10
```

**Authorization:** `Bearer {{token}}`

Query parameters:

  Parameter        Value Description
  -------------- ------- ------------------------------
  `pageNumber`       `1` Current page
  `pageSize`        `10` Number of customers per page

The API also supports the application's customer search parameter by
Full Name or Phone Number:

``` text
{{url}}/api/Customers?search=Nguyen&pageNumber=1&pageSize=10
```

### 3.2 Tạo Thông Tin Khách Hàng Mới

**Method:** `POST`\
**Endpoint:** `{{url}}/api/Customers`\
**Authorization:** `Bearer {{token}}`\
**Content-Type:** `application/json`

Request body currently stored in the Postman collection:

``` json
{
  "fullName": "Huỳnh Trần Trọng Nhân",
  "email": "nhanhtt1@outlook.com",
  "phoneNumber": "0968096974",
  "dateOfBirth": "1995-04-29T12:12:57.283Z",
  "isActive": true
}
```

`CustomerCode` is not supplied by the client. It is generated by the
backend.

### 3.3 Lấy Chi Tiết Thông Tin Khách Hàng

**Method:** `GET`\
**Endpoint:**

``` text
{{url}}/api/Customers/5
```

**Authorization:** `Bearer {{token}}`

In the current Postman collection, customer ID `5` is used as the sample
ID.

### 3.4 Cập Nhật Thông TIn Khách Hàng

**Method:** `PUT`\
**Endpoint:**

``` text
{{url}}/api/Customers/5
```

**Authorization:** `Bearer {{token}}`

Request body currently stored in the collection:

``` json
{
  "fullName": "Huỳnh Trần Trọng Nhân",
  "email": "nhanhtt1@outlook.com",
  "phoneNumber": "0968096974",
  "dateOfBirth": "1995-04-29T12:12:57.283Z",
  "isActive": true
}
```

`CustomerCode` is not part of the update request and is not modified by
this operation.

### 3.5 Xoá Thông Tin Khách Hàng

**Method:** `DELETE`\
**Endpoint:**

``` text
{{url}}/api/Customers/5
```

**Authorization:** `Bearer {{token}}`

The current collection uses customer ID `5` as the sample record to
delete.

### 3.6 Lấy Thông Tin Summarry

**Method:** `GET`\
**Authorization:** `Bearer {{token}}`

The Postman collection currently contains this request, but its request
URL is empty.

The implemented API endpoint used by the application is:

``` text
{{url}}/api/Customers/summary
```

Before submitting the Postman collection, set the request URL to the
endpoint above.

Expected summary data contains:

``` json
{
  "totalCustomers": 10,
  "activeCustomers": 8,
  "inactiveCustomers": 2
}
```

The numbers depend on the current database data.

## 4. Customer Validation

Customer Create and Update operations validate:

  -----------------------------------------------------------------------
  Field                               Rule
  ----------------------------------- -----------------------------------
  `fullName`                          Required; maximum 200 characters

  `email`                             Optional; must be a valid email
                                      when supplied

  `phoneNumber`                       Required; numeric characters only;
                                      maximum 20 characters

  `dateOfBirth`                       Optional; cannot be in the future

  `isActive`                          Boolean active status
  -----------------------------------------------------------------------

Validation is performed by the API even if a request is sent directly
from Postman.

## 5. Authentication Flow

``` text
POST /api/Auth/login
        ↓
Validate admin credentials
        ↓
API returns JWT
        ↓
Postman test script
        ↓
Collection variable {{token}}
        ↓
Authorization: Bearer {{token}}
        ↓
Customer APIs
```

## 6. Recommended Postman Test Order

Run the requests in this order:

``` text
1. Đăng Nhập
2. Lấy Danh Sách Khách Hàng
3. Lấy Thông Tin Summarry
4. Tạo Thông Tin Khách Hàng Mới
5. Lấy Chi Tiết Thông Tin Khách Hàng
6. Cập Nhật Thông TIn Khách Hàng
7. Xoá Thông Tin Khách Hàng
```

### Important note about IDs

The current Postman collection uses the fixed ID `5` for Get Detail,
Update, and Delete. Make sure customer ID `5` exists before running
those requests, or manually replace it with an existing customer ID.

## 7. Collection Variables

The collection currently defines:

``` text
url   = https://localhost:7137
token = ""
```

The `token` value is intentionally empty in the exported collection
because it is populated by the Login test script at runtime.

## 8. Notes

-   Start the API before executing Postman requests.
-   Run `Đăng Nhập` before protected Customer requests.
-   A valid JWT is required for Customer endpoints.
-   The Summary request URL should be set to
    `{{url}}/api/Customers/summary` before the final Postman export.
-   The current collection uses fixed customer ID `5` for
    detail/update/delete testing.
